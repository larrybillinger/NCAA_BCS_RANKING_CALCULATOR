# v0.8.2 — Daily polling with hourly Saturdays

Released 2026-09-27.

This is an operational scheduling change only. The ranking formula remains
`division_i_weighted_v5` and the predictor remains `rank_gap_v3`.

## Provider cadence

```text
Sunday-Friday:  once every 1440 minutes
Saturday:       once every 60 minutes
Full schedule:  at least once every 24 hours
```

The configured `TZ` determines the day boundary. Production normally uses
`America/Chicago`. If a daily sleep on Friday would extend into Saturday, the
worker wakes at local midnight and immediately begins the Saturday hourly cadence.

The worker still uses one unfiltered `/games` request per normal sync rather than
separate FBS and FCS calls.

## Browser refresh

Game Book and team pages reload every five minutes while a scheduled game is in
its normal live window. These browser refreshes query PostgreSQL and do not make
additional CFBD API requests.

## Rate limits

HTTP 429 handling from v0.8.1 remains in place. Provider requests back off
aggressively rather than retrying every few minutes.

## Production identifiers

```text
APP_VERSION=0.8.2
MODEL_VERSION=division_i_weighted_v5
PREDICTOR_VERSION=rank_gap_v3
```
