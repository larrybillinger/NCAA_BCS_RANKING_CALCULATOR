# Release v0.9.0

## Summary

v0.9.0 adds an admin-only manual score desk so D1 Rank can keep operating when CFBD is unavailable, delayed, or incorrect. This release does not change the ranking or prediction formulas.

## Changes

- New `/admin/games` score desk with week navigation and team search.
- Enter home/away scores and choose final or in-progress.
- Optional operational note.
- Active manual scores override provider score/final fields.
- "Release to CFBD" returns the game to provider control before the week is frozen.
- Game Book and team pages visibly label active manual finals.
- Manual result entry can complete a week and run the normal ranking/prediction pipeline.

## Security

- HTTP Basic authentication using `ADMIN_USERNAME` and `ADMIN_PASSWORD` from `.env`.
- CSRF validation on every write.
- Public routes remain read-only.
- Use the score desk only over HTTPS.

## Audit and integrity

- Every save/release is recorded in `manual_score_audits`.
- Prediction locking happens before a manual result is applied.
- Once the active production ranking model has frozen a week, manual score edits and releases for that week are blocked.
- CFBD cannot overwrite an active manual score override.

## Fixed Bugs

No ranking-formula bugs are changed in this release. The feature provides an operational fallback for external data outages and corrections.

## Known Issues

- Manual score entry requires that the game already exist in the local schedule database.
- Post-freeze score corrections intentionally require a separate deliberate recovery process; the score desk does not rewrite frozen history.
- The production admin page still requires Synology/HTTPS smoke testing after deployment.

## Upgrade Steps

1. Deploy from GitHub using `scripts/synology-update.sh`.
2. Existing installs automatically add the required game columns/table.
3. If no admin credential exists, the updater creates `ADMIN_USERNAME=admin` and a random `ADMIN_PASSWORD` in `/volume1/rankings/.env`.
4. Retrieve the password as root:
   ```bash
   grep '^ADMIN_' /volume1/rankings/.env
   ```
5. Open `https://<your-rankings-host>/admin/games` and authenticate.
6. Verify one non-frozen game can be saved and released.

## Rollback Notes

Application code can be rolled back from the normal app backup. The added PostgreSQL columns and audit table may remain safely in place; older application versions ignore them.
