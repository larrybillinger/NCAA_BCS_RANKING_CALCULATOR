# v0.11.1 — Winner-consistent projected scores

## Summary

v0.11.1 fixes a display bug introduced when `hybrid_core_v1` became the official predictor. The model could project a small but non-zero winning margin while the public site rounded both team scores to the same integer, producing misleading displayed ties such as 31–31 next to a 50.7% winner.

The ranking formula and hybrid prediction formula do not change in this release.

## Display rule

Projected scores now use one shared rule everywhere they are displayed or evaluated as integer scores:

1. round each continuous projected score half-up;
2. if the rounded scores are equal and the modeled margin is positive, add one display point to the home team;
3. if the rounded scores are equal and the modeled margin is negative, add one display point to the away team;
4. if the modeled margin is exactly zero, a displayed tie is allowed.

The adjustment is presentation-only. It does not change the continuous projected margin, projected total, win probability, ranking, or locked prediction inputs.

## Site-wide fix

- Game Book uses winner-consistent integer projected scores.
- Team schedule pages use the same display scores.
- Matchup Calculator uses the same display scores.
- Accuracy `display_tie_rate` uses the same rule instead of independently rounding each score.
- Existing PostgreSQL prediction rows do not need to be rewritten; the display result is derived from their stored continuous projection.

## Tests

Regression coverage includes:

- positive non-zero margins that would otherwise round to a tie;
- negative non-zero margins that would otherwise round to a tie;
- true zero-margin projections that may still display a tie;
- Accuracy display-tie accounting;
- Game Book/view-service score presentation.

## Separate accuracy investigation

GitHub issue #6 tracks the separate finding that the v0.11.0 leakage-safe hybrid retrocast reports 63.7% winner accuracy over 476 games while earlier project research had suggested a result around 72% for the promising hybrid configuration.

v0.11.1 intentionally does not alter the 40% rank-gap / 60% offense-defense weights, three-pseudo-game shrinkage, sample selection, or ranking model while that reproducibility issue is investigated.
