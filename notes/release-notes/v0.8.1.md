# v0.8.1 — Quota-aware sync reliability

Released 2026-09-27.

This release fixes the operational problem that left the production site stuck after CFBD began returning HTTP 429 responses. It intentionally does **not** change the `division_i_weighted_v5` ranking formula.

## Provider calls

A normal game refresh now uses one unfiltered `/games` request instead of separate FBS and FCS calls. Team statistics are likewise fetched with one request when a completed ranking week needs them.

Default polling:

```text
active game window:       every 60 minutes
idle:                     every 180 minutes
full schedule:            every 24 hours
first 429 cooldown:       360 minutes
maximum 429 cooldown:     1440 minutes
```

## Outage behavior

Prediction locking happens before any CFBD request. A provider failure can therefore delay new scores and rankings, but it cannot prevent an already-created pregame prediction from becoming official.

The target week for normal syncing comes from scheduled games nearest the current time rather than only from `latest ranking + 1`. A delayed ranking snapshot therefore no longer prevents the worker from refreshing the calendar week actually being played. The daily full-season schedule refresh catches moved games.

## Visibility

The sidebar reports:
- CFBD OK / stale / error / syncing;
- last successful sync;
- latest sync attempt;
- short provider error.

The `/health` endpoint exposes the same status programmatically.

## Browser refresh

Game Book and team pages automatically reload from PostgreSQL every two minutes while a game is within its normal six-hour live window. This does not make additional CFBD requests from the browser.
