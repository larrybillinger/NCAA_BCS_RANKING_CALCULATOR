# v0.10.2 — Game-aware live sync and team-identity repair

Released 2026-10-08.

This release fixes live score updates, closes a duplicate-team data-integrity
hole, and repairs affected production rankings. The ranking formula remains
`division_i_weighted_v5` and the official predictor remains `rank_gap_v3`.

## Live cadence

Up to v0.10.1 the worker polled CFBD hourly on Saturdays and once a day on every
other day. Weeknight games could therefore remain stale until the next daily
poll, and late Saturday games could fall back to the daily cadence after local
midnight.

v0.10.2 makes polling schedule-aware:

```text
Next Division I kickoff:           wake at kickoff
Any Division I game in progress:  every SYNC_LIVE_MINUTES (default 60)
No upcoming/live game:            at most every SYNC_IDLE_MINUTES (default 1440)
Full schedule refresh:            at least every 24 hours
HTTP 429:                         existing exponential cooldown
```

Waking at kickoff is deliberate. The worker runs local official and research
prediction locking before it contacts CFBD, so a pregame prediction becomes
locked on the kickoff cycle even if the provider is unavailable or rate-limited.

A game counts as live from kickoff until it is final in PostgreSQL, for at most
8 hours after kickoff. That keeps late games on the live cadence after midnight
without allowing a cancelled or never-finalized game to hold the worker there
forever.

## Team identity and Penn/Pennsylvania repair

The production database contained both `Penn` and `Pennsylvania` as active FCS
teams. The legacy `Penn` row came from data created before a durable CFBD team ID
was attached; later provider data used the current `Pennsylvania` name, and the
old upsert logic matched only by provider ID or exact name. That allowed two
active rows for the same school and polluted the Division I ranking pool.

v0.10.2 now:

- resolves provider teams by CFBD ID first;
- recognizes the known historical `Penn` -> `Pennsylvania` alias when a legacy
  row has not yet acquired its provider ID;
- reconciles active Division I membership only from a full-season game schedule,
  which contains FBS/FCS classifications;
- allows only about 2% of the existing active D-I pool to be absent from that
  schedule before refusing reconciliation, so a partial provider response fails
  closed instead of mass-deactivating teams;
- excludes inactive current-season teams from Team Index and Compare Teams.

The Synology updater runs a one-time, idempotent repair for the existing
Penn/Pennsylvania duplicate. It preserves retired-model snapshots for audit,
deactivates the legacy current-season row, repoints current game/stat references,
removes active `division_i_weighted_v5` snapshots beginning with the first week
that contained the duplicate, and rebuilds those weeks from the corrected game
and team data. Later weeks are rebuilt too because they depend on prior ranking
state.

Predictions tied to removed corrupted snapshots are removed with those snapshots.
They are not retroactively relabeled as official corrected predictions after the
fact; the database backup preserves the old production record for audit.

## Deployment safety

Before the production repair, `synology-update.sh` now creates:

- a PostgreSQL `pg_dump` backup;
- an application backup;
- a protected copy of the production `.env` file.

The updater stops web and worker containers during the controlled repair so the
old worker cannot write ranking snapshots concurrently. It then recreates both
containers and performs the normal health/version checks.

## Other fixes

- The sidebar marks data stale after 90 minutes while games are in progress.
- `/health` reports the number of live games.
- The conference dropdown follows the FBS/FCS selection, and "All" is
  highlighted only when no filter is active.
- The rank calculator validates ranks against the current pool size.
- The week dock lists every scheduled week and no longer shows a misleading "…".
- Game Book kickoff times use the configured local timezone.
- Accuracy uses only active-model locked predictions and avoids repeated
  calibration work that caused the production timeout.
