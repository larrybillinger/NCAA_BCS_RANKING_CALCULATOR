# v0.10.3 — Forward-only team-identity repair

Released 2026-10-08.

This release changes how the Penn/Pennsylvania duplicate from v0.10.2 is
repaired. v0.10.2 was merged but never deployed; deploy this release instead.
The ranking formula remains `division_i_weighted_v5` and the official predictor
remains `rank_gap_v3`.

## Why v0.10.2's repair was replaced

The v0.10.2 repair deleted every active-model ranking week from the first one
containing the legacy `Penn` row and rebuilt them. Every prediction locked
against those weeks was deleted with them. Rebuilt predictions are created after
kickoff, so they can never lock: the official accuracy ledger and the hybrid
shadow ledger would have restarted from zero. That conflicts with the rule that
official predictions are never rewritten, and the gain was small — the legacy
row has no games, so its only effect was one extra slot in the pool.

## What the repair does now

- Merges the legacy `Penn` row into `Pennsylvania` (CFBD ID match required).
- Removes the legacy row from the active 2026 pool.
- Repoints any game and team-stat references.
- Leaves every frozen ranking week and every locked prediction as published.
- Rankings calculated after the repair use the corrected pool.
- Refuses, changing nothing, if the legacy row has results in frozen rankings.

Running it again reports `"repaired": false`.

## Deployment

Use the same steps as v0.10.2: download the updater from `main` and run it. You
should see the PostgreSQL backup, then:

```text
Stopping application containers for controlled data repair...
Checking and repairing known duplicate team identities...
```

followed by JSON with `"repaired": true` and `preserved_weeks`. If the repair
refuses, the updater prints a warning and still restarts the site.

## Production identifiers

```text
APP_VERSION=0.10.3
MODEL_VERSION=division_i_weighted_v5
PREDICTOR_VERSION=rank_gap_v3
```
